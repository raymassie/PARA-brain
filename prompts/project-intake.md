# Project intake

Use before creating a new active project, or when its goal materially changes.
Read `Librarian.md` and the applicable project template. Reuse the current request
and relevant supplied context before asking for anything.

## Gather the missing facts

Gather an observable goal (what done looks like), start date, end date, and
whether the end is a firm deadline or a target. Batch only missing questions in
one short exchange. Either date may explicitly be `undecided`; never invent it
or silently use today as the start. Record accepted dates in ISO `YYYY-MM-DD`
format. Resolve relative dates from their source date and the user's timezone;
clarify ambiguity and an end before the start. Do not repeatedly ask about an
explicitly undecided date unless new information makes it material.

Ask about audience, deliverables, or constraints only when needed to make the
goal and initial actions useful. Resolve routine reversible choices independently
and label material assumptions. An ongoing responsibility without a finish line
belongs in Areas. If a missing fact blocks creation, report it and continue any
independent authorized work; do not create a project full of placeholders.

## Save one project and one checklist

Search for an existing project before creating another. A first note uses
`templates/project-note.md`. Promote to a folder and use
`templates/project-readme.md` only when a second substantive note joins it.
Preserve custom fields, original dates, completed work, and useful evidence on
promotion. The project's `started`/`Started` field is its actual stated start,
not the file creation date; retain any existing creation date separately.

Write a short actionable checkbox list: each item names a concrete action and
an observable completion check. Keep one canonical list in the note or README.
If the user designated an external live tracker, link to it rather than making
a competing list. Creating the local project does not authorize external writes.
Record a specific next action, blockers, and relevant decisions without inventing
scope or deliverables. Mark goal and dates as user-reported unless checked.

Read the saved result, confirm all placeholders are filled or explicitly
undecided/unknown, and follow `prompts/home-digest.md`. Report the saved path,
next action, and any material unresolved decision. A planned action is not an
executed result, and checked tasks alone do not prove the finish line was met.
